# 边缘格子折叠交互重设计

## 背景与动机

当前折叠交互通过点击折线触发：V/H 折线用 Button 热区，对角折线用距离检测。主要问题：

1. **中间折线方向不直观**：位于网格正中间的折线，折叠方向是自动选择"较小方"，但对于对称情况，玩家无法预判方向
2. **两套交互机制并存**：V/H 用 Button，对角线用自定义距离检测，实现不统一
3. **对角折线交互不精确**：22px 距离检测在手机上容易误触

## 设计概述

用**两次点击**取代**一次点击折线**：

1. 玩家点击一个**边缘格子**
2. 该格子通过所有可用折线能到达的**目标位置**显示金色发光脉冲
3. 玩家点击某个**目标格子**执行对应折叠

这彻底解决了方向歧义——玩家自己选目标，而非系统决定方向。

## 交互状态机

```
IDLE ──(点击边缘格子)──→ SELECTED ──(点击目标格子)──→ FOLDING ──(动画完成)──→ IDLE
  ↑                         │
  └──(点击已选格子/空白)────┘
```

### IDLE（空闲）

- 所有折线显示为虚线（纯装饰，不可点击）
- 边缘格子显示可交互提示（具体强度在游戏中调试确定）
- 玩家可点击任意**有效**边缘格子（非空 + 至少被一条折线影响）

### SELECTED（已选中）

- 被点击的边缘格子：白色高亮边框
- 目标位置：金色边框 + 外发光 + 呼吸脉冲动画
- 玩家可点击：
  - **目标格子** → 进入 FOLDING
  - **已选格子** → 取消，回到 IDLE
  - **非目标的空白区域** → 取消，回到 IDLE

### FOLDING（折叠中）

- 执行现有的折叠动画（不变）
- 动画完成后回到 IDLE

## 边缘格子定义

网格中满足以下条件之一的格子为边缘格子：
- `row == 0` 或 `row == size - 1`
- `col == 0` 或 `col == size - 1`

**额外条件：**
- 格子非空（未被之前的折叠清空）
- 至少被一条 `available_folds` 中的折线影响（在其源侧）

角落格子同时属于两条边，可能被更多折线影响，不需要特殊处理。

## 目标计算逻辑

玩家点击边缘格子 `(row, col)` 后，遍历所有 `available_folds`：

对每条折线 `fold_def`：
1. 判断 `(row, col)` 是否在该折线的**源侧**（较小方）
2. 如果是，计算镜像目标位置 `(target_row, target_col)`
3. 记录映射：`(target_row, target_col) → fold_def`

结果是一个字典 `target_map: {Vector2i → Dictionary}`，存储目标格子到折线定义的映射。

### V/H 折线的镜像计算

- **竖折 (v, pos):** `target_col = 2 * pos - 1 - col`，row 不变
- **横折 (h, pos):** `target_row = 2 * pos - 1 - row`，col 不变

### 对角折线的镜像计算

- **d_bs (offset):** `target_row = col - offset`, `target_col = row + offset`
- **d_fs (offset):** `target_row = offset - col`, `target_col = offset - row`

### 源侧判断

- **v (pos):** 格子在 `[0, pos)` 或 `[pos, size)` 中较小的一侧
- **h (pos):** 格子在 `[0, pos)` 或 `[pos, size)` 中较小的一侧
- **d_bs (offset):** 通过 `val = col - row` 与 offset 比较，选择格子数较少的一侧
- **d_fs (offset):** 通过 `val = col + row` 与 offset 比较，选择格子数较少的一侧

注意：对角折线上的格子（`val == offset`）不属于源侧，其象限会被部分折叠。对于边缘格子的交互，如果格子恰好在折线上，不将其视为有效源格子（这些格子的象限折叠已由模型自动处理）。

## 折线视觉改动

### 虚线样式

- 所有折线（V/H/对角线）从实线改为虚线
- 虚线参数：`dash = 8px, gap = 6px`（经典 `- - -` 风格）
- 实现：通过 `_draw()` 自定义绘制多段短线，或 Line2D + 自定义 shader
- 颜色：`#5C4033`，透明度 0.25（与现有保持一致）

### 折线延伸

- 折线两端各延伸出网格边框约 **12px**

### 移除的元素

- V/H 折线的 **Button** 节点（不再需要点击热区）
- V/H 折线的**悬停效果**（不再需要）
- 对角折线的**指示圆**（Polygon2D 端点圆）
- 对角折线的**距离检测逻辑**（`_input` 中的 `_point_dist_to_segment`）

## 发光效果规格

### 目标格子（SELECTED 状态）

- 金色边框：`#FFD700`
- 边框宽度：3px
- 外发光：`Gaussian blur` 模拟（通过额外的半透明边框或 shader）
- 呼吸动画：透明度在 `0.4 ↔ 1.0` 之间，周期 1.5s

### 被选格子

- 白色边框：`#FFFFFF`
- 边框宽度：3px
- 无动画（静态高亮）

### 边缘格子可交互提示（IDLE 状态）

- 具体视觉效果在游戏中调试确定（白色微弱边框 / 轻微放大 / 其他）
- 需要在实际游戏中测试不同强度

## 折叠动画

动画逻辑完全不变：

- **V/H 折叠：** 翻页动画（收缩 0.25s → 展开 0.25s），总计 0.5s
- **对角折叠：** 源格子淡出 0.25s → 刷新网格

唯一的变化是触发入口：从"点击折线/距离检测"改为"从 target_map 查找 fold_def，调用现有的 `_on_fold(fold_def)`"。

## 点击检测实现

在 `_input(event)` 中：

1. 检测 `InputEventMouseButton`（左键按下）
2. 将点击坐标转换为网格坐标：`cell = floor((click_pos - GRID_ORIGIN) / (CELL_SIZE + CELL_GAP))`
3. 验证坐标在网格范围内
4. 根据当前状态分发：
   - **IDLE：** 检查是否为有效边缘格子 → 计算 target_map → 进入 SELECTED
   - **SELECTED：** 检查是否为目标格子 → 执行折叠；否则取消

  - 新增发光效果绘制/动画
